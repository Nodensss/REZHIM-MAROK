# Android-приложение 3.2 — прошлые режимы и «переход: откуда → куда», 10.11.2026

Что добавлено поверх 3.1:

- **«Прошлые режимы»** марки: по карточке на каждый день, когда линия шла на этой марке, новые сверху, с главными цифрами (ПАЛ, ПТР, нагрузка, инициатор по зонам, уставки температуры). Карточка открывает весь режим дня с обычным разбросом марки и нормой техкарты. Два режима одной марки можно сравнить между собой.
- **«Переход: откуда → куда»**: оператор выбирает, с какой марки и на какую переходит. Нынешний режим берётся из последних снимков, из выбранного дня или вводится вручную (ПАЛ, нагрузка, инициатор и уставки по зонам, ПТР, пропилен, обороты); введённые цифры хранятся только на телефоне и в базу не пишутся. Сравнивать можно с последним режимом новой марки, с любым прошлым или со средним. По каждому параметру показано «сейчас → на новой марке», обычный разброс, норма и оценка «по прошлым сменам» — нынешняя цифра, умноженная на медиану отношения «стало / было» в прежних сменах между этими марками. Ниже — как такие смены шли раньше.
- Оба экрана открываются с главной, с вкладки «Смены», с экрана марки и из «Режима марки».
- Логика вынесена в `Regimes.java` (3 JVM-теста, `RegimesTest`). Всего JVM-тестов 32.

# Android-приложение 3.1 — смены марок и режим марки, 07.11.2026

Что добавлено поверх 3.0:

- **Вкладка «Смены»** вместо «Переходов». Это лента смен марки по месяцам, новые сверху. По каждой смене простыми словами показано «было → стало»: ПАЛ, инициатор всего и по зонам, доли зон полосками, уставки температуры зон, ПТР (анализатор, исходный, журнал), пропилен, нагрузка и обороты А-404. Строка «Главное» называет три самых заметных изменения: например, «ПАЛ — меньше в 3,2 раза». Переключатели: марка, «ближайшие снимки / среднее за период», «только сверенные». Ручная разметка переходов открывается кнопкой «Разметка переходов».
- **Размеченный переход** показывает время начала и окончания со слов оператора и ход перехода по точкам. Пока переход идёт, рядом с каждой цифрой «сейчас» видно, сколько было на прежнем режиме целевой марки на этой линии. Расходы инициатора, помеченные как смесь старого и нового раствора, подписаны и не участвуют в сравнении.
- **«Режим марки»** открывается кнопкой на экране марки. Для каждого параметра показаны: значение в последнем режиме, обычный диапазон по всем замерам марки (без точек перехода) и норма действующей техкарты. Значение вне нормы выделено. Ниже — все смены на эту марку и с неё.
- **Снимок базы** теперь переносит в APK переходы, размеченные на ПК (таблица `transition`), с замерами до, во время и после. Он же переносит примечания к замерам и признак «смесь растворов», а происхождение времени берёт из поля `time_source` распознавания (часы пульта, EXIF, журнал, оценка). В базе 72 замера, 867 значений, 129 исходников и 1 подтверждённый переход (20220 → 15803-020, 22.10.2026, 02:50–05:30).
- Логика смен вынесена в `Smeny.java` без Android-типов и покрыта 11 JVM-тестами (`SmenyTest`). Всего JVM-тестов 29.

# Android-приложение 3.0 — выполнено 25.09.2026

Работа по `output/TZ-prilozhenie-analiz-rezhimov-2026-09-25.md`. Готовый файл — **`output/Marki-UPE-3.0.apk`** (377 МБ). Он ставится поверх версий 1.3 и 2.0 и работает без сети и учётной записи. Выполнены этапы 1–5 ТЗ. Этап 6, локальная модель, не делался: по ТЗ он возможен только после накопления проверенных переходов.

## Что в поставке

- **Полная база внутри APK.** Скрипт `rezhim/android_snapshot.py` читает `data/rezhim.sqlite3` только на чтение и собирает снимок: 5 марок, 54 замера, 687 значений (102 подтверждены, 583 на сверке, 2 отклонены), 64 поля вне словаря, 8 техкарт, 56 норм, 76 строк рецептур и 743 записи истории. Рядом с ним в APK лежат все 82 исходных файла, из них 57 JPG. SHA-256 каждого файла сверяется с базой ещё при сборке. Выбран один большой APK: фото хранятся в нём без сжатия и открываются прямо из поставки.
- **Происхождение времени.** Для каждого замера указано, откуда взято время: 21 — с экрана, 23 — из EXIF, 4 — введены вручную, 6 — неизвестно. Время определено по заметкам распознавания и совпадению с EXIF, ничего не выдумано. Для марки тоже указан источник: пользователь, прототип, распознанный JSON или переназначение.
- **Дополнения телефона хранятся отдельно** от заводского снимка (`user-layer.json` в памяти приложения). Проверено: после обновления APK добавленные фото, значения и решения сохраняются.

## Экраны (раздел 8 ТЗ)

| Экран | Что делает |
|---|---|
| Главная | Счётчики, объём сверки, переходы и кандидаты, спорные записи, последние добавления |
| Марки | Поиск; таблица пропорций по снимкам (ПАЛ, F1–F3, FΣ, доли зон, ПАЛ/FΣ, C3, ПАЛ/C3, Q); техкарты с нормами и рецептурами; замеры; фото марки |
| Замер | Реквизиты с происхождением; значения раздельно: факт, уставка, выход регулятора, расчёт СУТП, лаборатория, поля вне словаря; нормы справочно; фото; история; правка реквизитов с причиной |
| Значение | Подтвердить (только при наличии фото), отклонить, исправить (старое число остаётся отклонённым), вернуть на сверку, отметить область на фото |
| Сравнение | Два замера: Δ и %Δ (%Δ не считается при нуле), доли зон, отношения и удельные расходы только при известных совместимых единицах, с причиной каждого отказа. Без подтверждённого перехода экран называется «Сравнение снимков» и прямо говорит, что это не переход и не уставка |
| Переходы | Кандидаты из хронологии с разрывом и предупреждениями; ручная разметка эпизода (начало, конец, устойчивые замеры до/после, промежуточные, уставки, задержка, выпуск, лаборатория, оператор) со шкалой; подтверждение только при полной разметке |
| Оценка сейчас | Текущие значения берутся из замера или вводятся вручную. По подтверждённым эпизодам пары — медиана и диапазон Δ с числом случаев. Подсказка подавляется, если случаев меньше 3, данные противоречат друг другу, текущие значения не проверены, режим вне исторической области или выходит за нормы целевой марки |
| Добавить фото | Системный выбор файлов; SHA-256 и поиск дублей; EXIF и время из имени файла показываются отдельно; марка, линия и время могут быть неизвестными; если марка в имени файла другая — отдельное подтверждение; объединение с замером того же момента — по вопросу |
| Сверка | Очередь по замерам с быстрыми решениями; спорная атрибуция 08220/80210 (14 одинаковых показателей) с вариантами решения; конфликты чисел и импорта |
| База и JSON | Проверка целостности (счётчики и SHA-256 всех файлов); выгрузка JSON, ZIP с добавленными или со всеми фото; импорт с предварительным итогом без удаления записей; версии базы и откат |

## Пересборка после изменений на ПК

```powershell
.\android_build.ps1
```

Скрипт собирает снимок из текущей базы, прогоняет JVM-тесты, собирает APK и кладёт его в `output\Marki-UPE-<версия>.apk`. Новый APK ставится поверх старого; дополнения телефона остаются. Номер версии задаётся в `android/app/build.gradle`. Проверить выгрузку с телефона на ПК:

```powershell
.\.venv\Scripts\python.exe -m rezhim.android_snapshot --verify путь\к\rezhim-ГГГГ-ММ-ДД.json
```

## Что не сделано

1. **OCR.** Числа вводятся вручную по фото с увеличением. Раздел 7 ТЗ это допускает: распознавание — отдельная функция после испытаний на реальных снимках.
2. **Локальная модель (этап 6).** Сейчас подтверждённых переходов 0. Модели нужны размеченные эпизоды и согласованные с технологом пределы.
3. **Приём выгрузки телефона в SQLite на ПК.** Выгрузка проверяется командой `--verify`, но в рабочую базу ПК автоматически не вливается.
4. **Данные.** 583 значения и 64 поля вне словаря ждут сверки. Пара 08220/80210 не решена. Устойчивость не отмечена ни в одном замере, фактического выпуска в т/ч нет ни в одном. Пока это так, «Оценка сейчас» будет честно отказывать.
5. **JS-тест мобильного PWA — исправлено 25.09.** `tests/domain.test.mjs` («unverified, conflicts and broken provenance rejected») падал с изменения `mobile/domain.mjs` от 22.09: пакет справочника снова принимается только с подтверждёнными числами без конфликтов; непроверенные значения допускаются лишь в полной базе с `includes_unreviewed: true`.

Исходники версии 2.0 до изменений сохранены в `tmp/android-src-2.0-backup`.
