# Режимы марок УПЭ

Локальное рабочее место для ручного ввода и сверки, SQLite и отдельный мобильный справочник PWA по ТЗ от 20.09.2026. Выполнена миграция марки 15803-020: три замера, нормы 54.2 и рецептура. Подробный актуальный результат — в [MIGRATION_REPORT.md](MIGRATION_REPORT.md); отчёт первой итерации сохранён как история в REPORT.md.

После миграции заполните А-103, АБ-124 и устойчивость в журнале: раскройте замер → «Признаки для профиля» → «Сохранить признаки». Экран «Профиль марки» показывает, чего не хватает каждому замеру. Неизвестная устойчивость отличается от явно указанного перехода; обновление признаков не меняет числа. Для телефона после правок соберите новый пакет.

## Запуск в Windows

1. Дважды нажмите ярлык «Режимы марок УПЭ» на рабочем столе или `start.bat` в папке проекта. Нужен Python 3.11 или новее; в текущем окружении проверено на Python 3.12.
2. Сервер запустится, а главная страница автоматически откроется в обычном браузере.
3. Оставьте окно «Rezhim UPE - Server» открытым. Закрытие окна или Ctrl+C останавливает сервер. Повторный запуск открывает браузер и использует уже работающий сервер.

Краткая инструкция без команд, включая проверку мобильного справочника на ПК и установку на телефон, — в файле `КАК ОТКРЫТЬ.txt`.

При первом запуске скрипт создаёт `.venv` и устанавливает Flask из `requirements.txt`; для установки нужен интернет. После установки рабочее место работает локально. На этом ПК окружение уже подготовлено.

Ручной запуск:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m rezhim.app
```

Приложение слушает только `127.0.0.1`. Это локальный инструмент без учётных записей. Не публикуйте настольный Flask-сервер в сеть.

## Первый замер

1. В «Справочниках» добавьте марку.
2. Проверьте единицы параметров по реальным источникам. Для расходов с неизвестными единицами числа не принимаются до явной настройки. Для безразмерных величин можно задать `1`.
3. Во «Вводе и сверке» выберите марку, линию, время с экрана, состояния оборудования и тип экрана. Неизвестное состояние сохраняется именно как неизвестное.
4. Загрузите JPEG, PNG или PDF. Файл копируется в локальное хранилище и получает SHA-256.
5. Введите значения. Запятая и точка поддерживаются. Пустое поле — пропуск; для ошибки исходника есть отдельный пункт статуса. Подтверждайте только сверенные числа. Устойчивость имеет три состояния: «не указано», «устойчивый», «переход».
6. Укажите техкарту, версии рецептур зон 1–2 и зоны 3, если они известны. Насосы назначаются по схеме «зона → насос».
7. Сохраните. Второе фото того же момента и линии дополняет замер. Разные реквизиты такого эпизода отклоняются, а разные числа одного параметра создают очередь сверки.
8. В журнале откройте замер и исходники. Подтверждение одного варианта отклоняет остальные варианты параметра в этом замере. История решений записывается в таблицу `audit`.

Состояния СУУТП «измерение» и «расчёт» представлены разными параметрами. Никакого пересчёта по току экструдера нет.

## Техкарты

Загрузите документ через экран ввода, затем добавьте версию техкарты в справочниках. Укажите даты действия, источник, нормы, разделы и номера строк. Периоды одной марки не должны пересекаться. Замер может ссылаться только на техкарту своей марки, действовавшую на его дату.

Версии в этой итерации создаются без последующего редактирования. Если дата завершения известна, укажите её сразу. Закрытие периода ранее созданной открытой версии и исправление её реквизитов через интерфейс — следующий этап. Условные исключения из норм пока не исполняются; их можно сохранить в примечаниях, но они не меняют проверку границ.

## Пакет и телефон

«Пакет для телефона» создаёт JSON с возрастающим номером версии. Экспортируются только подтверждённые числовые значения, связи с источниками, реквизиты, справочники и нормы. Фото остаются на ПК; телефон получает имена файлов и SHA-256.

Мобильная часть доступна локально по http://127.0.0.1:5000/mobile/. Для настоящего телефона каталог `mobile` нужно разместить на HTTPS-хостинге как самостоятельную статику, затем открыть и установить приложение. Размещение на хостинге в эту итерацию не входило. Открытие `index.html` с диска и HTTP по LAN-IP не дают требуемого офлайн-режима PWA.

На телефоне откройте «База», импортируйте JSON и сохраните резервную копию. Пакет хранится в IndexedDB; интерфейс кэшируется service worker. Повторный пакет не меняет базу, более новая версия заменяет её одной транзакцией, более старая требует подтверждения. Одинаковый номер с другим содержимым отклоняется.

В профиле марки обязательны линия, известная конфигурация, техкарта и обе версии рецептур. Показываются медиана, квартильный диапазон, минимум, максимум, число эпизодов и производительность. Это описательная статистика выбранных устойчивых замеров, без расчёта ожидаемого режима на заданную нагрузку. Значения разных параметров не следует трактовать как один реально наблюдавшийся режим; ссылки ведут на отдельные исходные замеры.

При изменении файлов мобильного интерфейса увеличивайте имя кэша в `mobile/sw.js`. Обновление service worker не удаляет IndexedDB.

## Смены марок

Страница сравнения соседних по времени режимов: календарь по месяцам и лента смен марки: для каждой смены простыми словами — что было, что стало и насколько (ПАЛ, инициатор, доли по зонам, температуры зон, ПТР, привод), остальное и нормы техкарт в «Подробнее». Внизу — сравнение любых двух замеров. Соседние снимки разных марок — кандидаты, а не подтверждённые переходы.

На ПК: кнопка «Смены марок ↗» в рабочем месте (адрес http://127.0.0.1:5000/smeny/, всегда по текущей базе). Отдельный файл для телефона или пересылки: `python -m rezhim.smeny_page` → `output/smeny-marok.html`, открывается без сервера.

## Android-приложение

Версия 3.1 (07.11.2026) добавила вкладку «Смены» (лента смен марки простыми словами, ход размеченного перехода) и экран «Режим марки»; APK собирается в GitHub Actions и выкладывается в релиз `v3.1`. `output/Marki-UPE-3.0.apk` — офлайн-приложение по ТЗ от 25.09.2026: вся база и фото внутри APK, сравнение снимков и пропорции, сверка, добавление фото, разметка переходов, оценка по подтверждённым аналогам, обмен JSON/ZIP. Исходники — `android/`, снимок базы собирает `rezhim/android_snapshot.py`, пересборка — `android_build.ps1`. Подробности и ограничения — в [ANDROID_REPORT.md](ANDROID_REPORT.md).

### GitHub

Репозиторий приватный: в нём производственные фото и база. APK (≈360 МБ) и `15803020.pdf` больше лимита git в 100 МБ, поэтому лежат в разделе **Releases** — там и скачивается готовый APK.

- **Изменить и собрать на GitHub:** закоммитьте правки в `main` — Actions прогонит тесты ПК и Android. Чтобы получить APK, откройте Actions → «Android APK» → Run workflow: готовый файл появится в релизе `v<versionName>`. Для новой версии сначала поднимите `versionCode` и `versionName` в `android/app/build.gradle`.
- **Собрать на ПК:** `.\android_build.ps1` → `output\Marki-UPE-<версия>.apk`.
- APK подписывается одним и тем же ключом (локально — `~/.android/debug.keystore`, в Actions — секрет `DEBUG_KEYSTORE_BASE64`), поэтому новая сборка ставится поверх старой без потери данных телефона.
- Папка `data/` хранится в репозитории: из неё собирается база внутри APK. Перед коммитом базы остановите настольное приложение.

## Файлы и резервные копии

- `rezhim/` — Flask API, схема SQLite и стартовый словарь.
- `web/` — настольный интерфейс.
- `mobile/` — самостоятельный мобильный интерфейс без внешних ресурсов.
- `screen_templates/` — пять стартовых JSON-шаблонов. Это начальные наборы полей, не полный перенос экранов прототипа; редактируются в файлах.
- `data/rezhim.sqlite3` — эталонная база.
- `data/sources/` — оригиналы загруженных файлов.
- `tests/` — автоматические проверки на синтетических данных.
- `REPORT.md` — отчёт о выполненной итерации и оставшихся этапах.

Полная резервная копия рабочего места — **вся папка `data` при остановленном приложении**. JSON для телефона не содержит фото, сомнительных/отклонённых значений и журнала решений, поэтому полную копию не заменяет. Для восстановления верните папку `data` до запуска.

Для изолированных проверок можно задать переменные `REZHIM_DATA` (отдельная папка базы) и `REZHIM_PORT` (порт). Не используйте производственную базу для тестов.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/domain.test.mjs
```

Node нужен только для тестов мобильной логики. Для работы приложения он не требуется.
