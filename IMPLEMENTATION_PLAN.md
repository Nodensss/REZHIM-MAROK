# План: локальное распознавание фото

Источник требований: `ТЗ распознавание фото в rezhim-desk.pdf`, 21.09.2026.

## Принципы

- Работа только на локальном ПК. Фото и результаты не отправляются в сеть.
- Результат OCR никогда не становится значением замера автоматически. Он всегда создаёт кандидата со статусом «требует сверки» и ссылкой на исходное фото.
- Ручной ввод и импорт JSON остаются без изменений.
- Каждое решение оператора и исходный текст OCR попадут в журнал.

## Этапы

1. **Основание OCR — выполняется сейчас.** Ввести единый интерфейс движка, самопроверку PaddleOCR/Tesseract, скрипт точности по размеченному набору и API статуса. Критерий: приложение честно сообщает готовность движка и умеет посчитать точность полей и ложные привязки, не меняя базу.
2. **RulerControl.** Находить строки по латинскому тегу, брать число из той же строки, сопоставлять тег со словарём и создавать кандидаты для сверки.
3. **А-329.** Читать колонки насосов, отдельно подтверждать расстановку по зонам и только затем связывать числа с ключами зон.
4. **Пачки фото.** Принять папку или заметку Markdown, извлечь время из имени или EXIF, разбить на замеры с разрывом 15 минут, показать разбиение до OCR и не повторять SHA-256-дубликаты.
5. **Проверки и сверка.** Добавить допустимые диапазоны, предупреждения норм, межэкранные конфликты, варианты типичных подмен цифр, вырезки строк и горячие клавиши.
6. **СУУТП и горячая вода.** Добавить обработчики экранов MV/CV и мнемосхемы.
7. **Пилот.** Запустить на размеченных снимках, сохранить метрики по типам экранов, время сверки и примеры ошибок. Включать распознавание по умолчанию только после 95% верных полей на крупных планах и нуля ложных привязок среди прошедших проверки.

## Стартовый набор пилота

Для первого прогона нужны сами фотографии: кадры А-329 и общих окон для замера 21.09.2025 16:19 (линия А), а также A_общий и А-329 от 20.09.2026. После добавления файлов создаётся `data/pilot/annotations.json`: ожидаемый ключ и точное число для каждого проверенного поля. Скрипт сравнивает только полностью совпавшие поля; похожее число или верный ключ с другим числом не засчитываются.
